## 准备被控端

在要控制的 Mac 上安装 Removent，[授予权限](/docs/permissions)，并从菜单栏启用共享。建议首次配对时让两台 Mac 位于同一个可达网络。

## 发现或添加主机

Removent 通过 mDNS 发现附近主机。在控制端打开应用，从设备列表选择目标 Mac。

设置中可分别开启 Removent、VNC 和 RDP 发现；Removent 默认开启，VNC 与 RDP 默认关闭。从 v0.1.4 开始，桌面端和移动端仅使用 Bonjour/mDNS 服务广播。未广播的服务器需要手动添加，也可指定自定义端口。

关闭协议开关会停止其发现并移除相应列表项。点击 VNC/RDP 设备会预填连接地址，凭据仍由你输入，不自动建立信任。

如果未发现设备，选择**添加连接 → Removent** 并输入地址。访客网络、VLAN 或客户端隔离可能阻止发现，即使手动输入地址仍可以连接。

协议需要明确选择。更换端口不会把 Removent 连接变成 VNC 或 RDP。

## 配对与授权

输入被控端显示的 PIN，由被控端批准请求的访问权限。原生 RVP 使用 SPAKE2 配对、固定设备证书和双向 TLS。

配对后，受信任设备可以在已授予的能力范围内重新连接。新增能力仍需批准；如果主机设置为拒绝传入连接，已配对设备也无法绕过。

## 选择主机认证方式

在被控 Mac 的**设置 → 安全**中选择认证方式。桌面控制端和 iPhone/iPad App 会自动遵循主机策略：

- **配对码**：输入主机显示的六位 PIN，或主机生成的一次性十二位连接码。主机可选择记住设备或每次连接都重新配对。
- **访问口令**：输入主机设置的口令，已配对设备也需要验证。
- **验证器 OTP**：输入已绑定验证器的当前六位验证码，验证码会过期且不可重复使用。
- **无认证**：不显示凭据输入提示，RVP 仍使用加密传输和主机证书校验。

口令和 OTP 使用 SPAKE2 证明及双方签名确认，不发送明文凭据。这些模式适用于直连和私有中继。relay 的访问口令与设备授权独立于主机凭据校验。禁止传入连接时，所有模式都会被拒绝。修改主机策略会使旧策略下的快速恢复失效，需要重新连接并输入新凭据。

## 会话中的操作

将指针移到窗口顶部边缘可显示会话工具栏，远端画面始终是窗口的主体。

性能信息默认隐藏。可使用工具栏的仪表图标或 **Control + Command + I** 切换显示。**Control + Command + Escape** 是本地逃逸快捷键。

[画面质量](/docs/quality)介绍原生会话如何适应网络变化。

## 不在同一个网络

配置[私有中继](/docs/relay)，然后在 Removent 连接表单中选择**通过中继连接**。中继负责网络可达性，设备配对与主机授权仍然需要完成。
