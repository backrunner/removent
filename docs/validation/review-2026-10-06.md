# Connection and authentication review — 2026-10-06

Reviewed the complete pending changes across desktop, mobile, CLI, daemon, tray, discovery,
authentication, invitations, TLS, both relay transports, Cloudflare control and documentation.
The review includes earlier authentication and connection-code work, not only the connection form.

## Corrections

- Shortened English and Chinese placeholders. Native address fields mention connection codes;
  VNC/RDP fields only mention IP addresses and hostnames. Relay access credentials use the label
  “Relay access password”. SNI defaults to the relay hostname. The form has no fingerprint input
  or indented Advanced section.
- Scoped each mobile certificate alert to a unique prompt ID. Dismissal of a relay alert cannot
  answer or cancel the following computer alert. Consecutive alerts wait for the previous
  presentation to finish.
- Disabled relay certificate verification bypasses existing local pins as well as supplied pins,
  and does not replace the remembered identity. Verified connections still reject mismatches.
- Trust prompts show the resolved computer address, or relay room and endpoint, instead of
  internal invitation routing identifiers.
- Closed TLS certificate probes before waiting for user consent. Reconnection checks the exact
  approved certificate before opening application streams or sending authentication credentials.
