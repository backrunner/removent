# 最近修改与 VNC 兼容性审查（2026-09-16）

> 历史审查记录。2026-09-20 起按用户要求清理开发 beta，不再提供其更新、协议或后台服务迁移兼容；下文保留当时的验证证据。

范围：`879143d..b4a2f34` 中的 VNC 与连接改动，重点复查 beta.4 之后的收藏、钥匙串、后台服务迁移及更新器，并处理 9 月 13 日报告中的八项业务问题。开始时工作区干净。修复保留在工作区，尚未发布安装包。

本次确认并修复了协议、生命周期和数据一致性问题；自动回归通过。**不能据此宣称没有任何 bug，或支持所有厂商的所有 VNC 认证模式。** 用户没有可用于验收的远端服务，Apple 实机、商业 VNC 产品、签名安装包升级及长期弱网验证仍未完成。

## 修复

| 优先级 | 问题与修复 | 主要位置 |
| --- | --- | --- |
| P1 | RFB 3.7 + None 不发送 SecurityResult，原客户端会等待超时，原服务端会把 ServerInit 前置四个错误字节。双方按 RFC 6143 附录 A 区分 3.3/3.7/3.8。 | `client/src/vnc/auth.rs`、`host/src/vnc/protocol.rs` |
| P1 | 3.3 的 32 位认证类型被截断为 8 位，257 可误判为 None。现在只接受该版本允许的 1/2；错误 greeting 的分隔符和换行也会被拒绝。 | `client/src/vnc/auth.rs` |
| P1 | 把 Apple type 35 当作 type 30 的 DH 协议会卡住。现在仅协商已实现的 type 30；只提供 35 或其他未实现认证时立即返回明确错误，不再假装支持。 | `client/src/vnc/auth.rs` |
| P1 | 内置服务端的画面 socket 写入阻塞会阻塞按键释放。写入移至独立任务，保持最多一个发送中的包和最新画面；超时、取消及异常仍触发输入清理。 | `host/src/vnc/writer.rs` |
| P1 | 旧 launchd 任务的 bootout 参数错误，且更名会丢失登录偏好。使用完整 service target，处理与当前数据目录对应的旧 hash 标签，保留登录注册并等待旧进程退出。 | `core/src/service.rs` |
| P1 | 临时数据目录的 tray 会删除正式安装的旧登录项。迁移和开关现在同时检查 bundle 身份及默认数据目录，先写新注册再移除旧注册；迁移期间禁止重复操作。 | `StatusBarController.swift`、`TrayLogin.swift` |
| P2 | 未声明桌面尺寸更新能力；Apple 零尺寸初始化后收到空更新不再请求画面。现在声明 DesktopSize/ExtendedDesktopSize/LastRect，继续零尺寸探测，尺寸变化后请求完整画面。失败的 ExtendedDesktopSize 回复不修改 framebuffer。 | `client/src/vnc/framebuffer.rs` |
| P2 | LastRect 等没有改变画面的消息也复制并发布整帧。现在跟踪实际变化；推断尺寸超过 RFB 的 16 位范围时拒绝，避免后续请求截断。 | 同上 |
| P2 | VNC 会话内部读写错误仅写日志，UI 可能当作正常结束。通过 completion 通道上报协议/网络错误；发送加入 10 秒超时，异常关闭双向 socket。 | `client/src/vnc.rs`、`input.rs`、`app/src/engine.rs` |
| P2 | 服务端不支持常见 8 位 true-colour，且忽略不支持的像素格式后继续发旧格式造成花屏。新增 8 位输出，不支持的格式明确关闭连接。 | `host/src/vnc.rs`、`framebuffer.rs`、`writer.rs` |
| P2 | 收藏编辑地址或账号产生重复记录。表单携带稳定 id 原位编辑；新建仍按端点去重，编辑到已有端点明确报错。新增独立保存动作。 | `client/src/saved.rs`、`app/src/ui/connection.rs` |
| P2 | 旧窗口 touch 会覆盖新编辑、复活已删记录；并发读改写丢收藏。所有修改在跨进程锁内读取最新文件；touch 只按 id 更新时间，不重新插入。重连前刷新列表。 | `client/src/saved.rs`、`app/src/ui/home.rs` |
| P2 | 钥匙串失败后 JSON 状态与旧密码不一致。新密码使用独立版本项，成功后才提交引用；保存失败保留旧收藏与原有凭据。清空后的记录不再查询旧密码，即使旧项删除失败。失败会显示；保存警告独立于连接进度。 | `client/src/saved.rs`、`app/src/engine.rs`、`ui/home.rs` |
| P2 | 收藏保存和删除涉及钥匙串、跨进程锁，可能阻塞 UI。移入后台执行，取消会丢弃 UI 后续任务，防止保存结束后又发起已取消的连接。 | `app/src/ui/home.rs` |

没有弱化更新器的签名验证。beta.4 固定旧 bundle identifier，仍不能仅靠新版本代码修复其内置更新限制；更名后的安装需要手动重装与权限验收。

## VNC 支持与验证矩阵

| 路径 | 本次验证 |
| --- | --- |
| RFB 3.3 / 3.7 / 3.8，None / VNC DES 密码 | 客户端和内置服务端的 TCP 回归；另外与独立 **LibVNCServer 0.9.15** 完成六种组合的互操作 |
| Apple `RFB 003.889`、ARD type 30 | 合成服务端验证 DH/AES 凭据、普通 RFB 右键/中键顺序、Session Select、零尺寸初始化；**不是 macOS 实机验收** |
| Raw / Hextile / CopyRect | 手工编码样本、边缘 tile、颜色继承、重叠复制、畸形数据测试；独立 LibVNCServer 验证 Hextile 协商、CopyRect、尺寸变化及右键 |
| 桌面变化 | DesktopSize、ExtendedDesktopSize 失败回复、LastRect、Apple 零尺寸后空更新及首次 Hextile |
| 输入压力 | 4K Raw 数据暂停时发送 1000 个按键事件；50,000 次相邻运动输入合并且保留按键顺序；4K 解码主动让出执行时间；服务端 32 字节阻塞传输下释放按键 |
| 生命周期 | 畸形画面上报错误并关闭连接；命令通道关闭、握手超时、发送失败和取消清理 |

**尚不支持**：Apple type 35、VeNCrypt/TLS、RealVNC 私有认证、UltraVNC MS-Logon 等未实现的安全类型。服务端需要提供 None、VNC password 或 ARD type 30。未实现的 Tight/ZRLE 不会被声明；符合 RFB 的服务端可退回 Raw 或选择 Hextile。内置服务端仍输出 Raw，支持 8/16/32 位 true-colour，不提供索引色调色板。

RFC 依据：[RFC 6143](https://www.rfc-editor.org/rfc/rfc6143.html)，附录 A（握手）、7.7.2（CopyRect）、7.7.4（Hextile）、7.8.2（DesktopSize）。独立互操作库来自 [LibVNCServer 0.9.15](https://github.com/LibVNC/libvncserver/releases/tag/LibVNCServer-0.9.15)，只在临时目录构建，不作为产品依赖。

## 性能证据与限制

客户端新增 Hextile 和 CopyRect，保留 Raw 回退。Hextile scratch buffer 固定为一个 16×16 tile（1024 字节）；CopyRect 在现有 framebuffer 内进行可重叠复制。画面仍使用有界的最新值通道，不积累历史帧。

本机开发测试中，一个 **3840×2160 纯色合成画面**的 Hextile 像素负载为 **32,404 字节**，Raw 为 **33,177,600 字节**；一次完整解码耗时 **9.12 ms**。这是极易压缩的样本，不代表真实桌面、视频内容、端到端延迟或稳定帧率。测试同时检查解码期间输入任务可以运行。压缩路径的处理时间统计不计入读取网络数据的等待。

未进行长时间连续运行、睡眠唤醒、弱网丢包、真实 Retina 多显示器及各商业服务端压力验收；不能作全负载稳定性保证。

## 复跑独立互操作

将 LibVNCServer 0.9.15 构建到临时目录（CMake 4 需要 `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`）。用源码 `include` 与生成的 `build/include` 头文件编译 `crates/client/tests/fixtures/libvncserver.c`，链接临时构建的 `libvncserver` 并设置其运行库搜索路径，然后运行：

```sh
rtk proxy env REMOVENT_LIBVNCSERVER_FIXTURE=/absolute/path/to/fixture \
  cargo test --locked -p removent-client --lib \
  independent_libvncserver_interoperability -- --ignored --nocapture
```

fixture 只监听 IPv4 loopback，使用合成像素及固定测试密码，不读取或写入真实远程桌面。
