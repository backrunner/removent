# Implementation review (2026-09-07)

Reviewed the current working tree, including the existing uncommitted connection UI,
RDP, VNC, media and lifecycle changes. Existing changes were preserved.

## Correctness fixes

- **Input congestion:** pointer motion no longer consumes the entire control FIFO;
  one quarter of its capacity is reserved for ordered key/button/scroll transitions.
  If a transition still cannot be queued, the engine closes that session with a
  visible reason so it cannot silently continue with missing release events.
  Memory stays bounded and sends do not block the UI.
- **VNC keyboard:** non-Latin characters now use X11 Unicode keysyms. Named keys
  retain their protocol keysyms when GPUI supplies control/private-use characters.
  Repeats and releases reuse the original pressed keysym even after Shift changes
  or focus loss removes `key_char`. Unicode-only text emits a complete down/up pair.
- **VNC mouse:** vertical and horizontal wheel pulses preserve the held mouse
  button mask; scrolling during a drag no longer releases the drag button.
- **VNC host:** standard Backspace, Tab, Return and Escape keysyms are recognized
  in addition to the older control-character aliases.
- **Caps Lock:** viewer key events retain the lock state received in the separate
  modifier notification. In particular, RDP no longer synchronizes Caps Lock off
  on the first ordinary key after it was turned on. Focus loss releases held
  modifiers while preserving the lock toggle.
- **VNC lifecycle:** both socket halves belong to one session task. If either loop
  stops, the other is dropped and the frame channel closes, avoiding a frozen
  viewer after the input writer exits.
- **Native pairing cancellation:** the pairing task now aborts on every exit from
  connection setup, including cancellation while the PIN dialog still holds its
  sender. The host is released promptly instead of waiting for the PIN timeout.
- **IPC cancellation:** the app retains incomplete JSON and UTF-8 bytes across
  `select!` cancellation by polling or outbound requests; messages no longer lose
  their prefix when delivered in fragments.
- **IPC size limit:** the reader enforces the limit while buffering, without
  waiting for a newline or EOF from an oversized message.
- **Admission cancellation:** a drop guard removes an outstanding admission and
  broadcasts denial when the enclosing host timeout or shutdown cancels the
  request. Late replies are rejected and management dialogs can close.

- **Discovery lifecycle:** advertiser drop sends a goodbye and shuts down its
  mDNS daemon. The last browser owner also shuts down its daemon; a disconnected
  event source terminates the publisher instead of entering a busy loop.
- **Discovery expiry:** peers are retained until mDNS reports removal/record
  expiry. The independent 45-second timer could evict a healthy peer before the
  library refreshed its longer-lived DNS records.

## Validation

Regression coverage exercises motion floods and transition overflow, exact VNC
wire bytes, character release after modifier changes, scrolling while buttons are
held, Caps Lock propagation, fragmented UTF-8 cancellation, oversized unterminated
IPC messages, cancelled admission, cancelled native pairing with a live PIN dialog,
VNC writer shutdown while the server keeps its write half open, and discovery
daemon/publisher shutdown after their last owner is dropped.
The existing full-session test was also corrected: after waiting 400 ms for
clipboard handling, it can only require one retained video frame from the earlier
burst because the video channel now stores the latest frame. It still checks frame
size, audio, input, pairing, clipboard and negotiation; hardware codec roundtrip
tests separately exercise repeated frame encoding/decoding.

- `cargo clippy --workspace --all-targets -- -D warnings`: passed.
- `cargo fmt --all --check` and `git diff --check`: passed.
- `bash tray/Tests/run_integration_test.sh`: passed.
- `cargo test --workspace --no-fail-fast -- --test-threads=1`: not fully green.
  The run before the discovery cleanup passed 202 tests and failed only mDNS
  self-discovery. The final broader run passed the app, RDP interoperability,
  native session, core/daemon, host, media, input, protocol and QUIC integration
  targets, but again hit `AddrNotAvailable` in five localhost VNC tests and the
  existing mDNS self-discovery failure. The VNC target had passed all 39 tests in
  the preceding run with the same VNC implementation.
- The final discovery shutdown regressions both pass. The advertiser test itself
  needed to handle a status request queued behind shutdown: that request need not
  receive a response, so it now polls with a bounded wait for daemon termination.
- App tests were rerun after the Caps Lock focus-loss and localized-message changes:
  all 26 passed.

Some test attempts encountered macOS `AddrNotAvailable` on localhost TCP connects;
read-only inspection found tens of thousands of TCP connections/TIME_WAIT records
on this machine. The same VNC tests, including the new shutdown regression, passed
on the subsequent serial run. No system network settings or unrelated processes
were changed. The mDNS self-discovery test also failed during the baseline run
before these fixes.

## Remaining limitations

The earlier report's adaptation and codec scheduling work remains: the app does
not periodically send receive/decode statistics, and the serial video writer does
not build the queue depth assumed by `SendGate`. Full adaptation needs measured
transport pressure and applied FPS/scale changes, with constrained-network tests.
Synchronous software codec work still shares Tokio workers. These require a
separate pipeline change; this review does not claim they are fixed.

Real two-machine ScreenCaptureKit/TCC flows, Windows/macOS interoperability outside
the local fixtures, constrained Wi-Fi and long-duration media sessions were not
validated in this pass.
