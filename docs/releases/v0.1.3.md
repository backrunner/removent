Removent `0.1.3` brings the `0.1.3` beta series to the stable channel. RVP protocol remains v1. The desktop app requires Apple Silicon and macOS 26 or later; the standalone relay supports Linux x86_64 / ARM64 and macOS Universal on macOS 13 or later.

## Desktop and background service

- The menu bar opens a branded SwiftUI panel with service status, connections, login preferences and an Options menu. The permission section disappears once Screen Recording and Accessibility are both granted, and remains available when either permission is missing.
- Hosting permission status and requests come from the background host that performs capture and input control. First-launch requests are recorded to avoid repeated prompts after denial or service recovery.
- The host ships in a dedicated RemoventHost app bundle. Upgrading from an older host identity may require granting Screen Recording and device-control access to the new signature in System Settings.
- Explicitly stopping the background service persists across desktop/tray reopening and login. The tray and launchd recover unexpected daemon exits without overriding a deliberate stop, and concurrent starts remain serialized.
- Independent Removent, VNC and RDP discovery controls, refined device and saved-connection rows, configurable authentication, and improved light/dark theme feedback.
- Corrected VNC mouse coordinates when the viewer title bar is present.
- Stable and Beta update channels use SemVer precedence and signed manifests. Both channels can upgrade an earlier `0.1.3-beta.N` installation to this stable release without allowing a downgrade.

## Cloud sync and packaging

- Cloud sync publishes persisted state immediately at startup and recovers its helper without duplicate owners. Saved connection payloads use encrypted CloudKit records in the existing shared container; passwords, Keychain references, pairing secrets and certificate exceptions are excluded.
- The signed `0.1.3-beta.3` helper completed real CloudKit Production create, download, update and logical-deletion exchanges between two isolated local stores on one Mac. Physical Mac/iPhone convergence remains unverified. See the [validation report](https://github.com/backrunner/removent/blob/v0.1.3/docs/validation/cloudkit-production-2026-10-09.md) for the tested revision and remaining acceptance.
- Developer ID signed and notarized macOS ZIP / DMG installers include the desktop, host, tray and provisioned CloudKit helper. Packaging verifies the signing certificate, profile, container and Production entitlements, and stages a complete bundle before replacing the previous build.
- Local installation verifies the source fingerprint, preserves app and host signing identities independently, retains the installed CloudKit profile, and preserves existing data and login preferences.
- Expanded permission, startup, theme, signing and lifecycle regression coverage, with compatibility fixes for the current Rust toolchain and repository layout checks.

## Private relay

- Prebuilt static Linux x86_64 / ARM64 binaries and a signed, notarized macOS Universal binary, with checksum-verified installation and native service management.
- Optional automatic installation of signed stable updates, disabled by default. Configure `[updates] enabled = true` and `check_interval_secs = 86400`, then restart. Applying an update briefly interrupts relay connections.
- `removent-relay check-update` checks without installing. Update signatures, archive and binary SHA-256 hashes, platform and configuration compatibility are verified before activation.
- Local logs rotate at 8 MiB with three backups; one relay process runs per identity directory. Cloudflare management uses the deployment scripts and dashboard, while container updates follow deployment.

```sh
curl -fsSL https://raw.githubusercontent.com/backrunner/removent/v0.1.3/scripts/install_relay.sh | sh
```

Existing relay identities, credentials, configuration and stopped-service state are preserved. Restart an existing relay explicitly after installation.

This release replaces the latest stable release and supplies the Stable client and relay update feeds. Lock-screen / LoginWindow support and Cloudflare public-network performance retain their existing environment-specific acceptance requirements. The CloudKit validation above does not establish physical-device convergence, Production push delivery or extended network-failure recovery.
