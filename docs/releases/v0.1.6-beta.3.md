Removent `0.1.6-beta.3` fixes native remote sessions that disconnect immediately or remain waiting for video while the host display is asleep.

- After authentication and admission, the host wakes the display and waits for an actual capture source before accepting the session. Reconnecting sessions use the same preparation. The host keeps the display awake for the session and releases its power assertions when the session ends, without changing Energy Saver settings.
- An unavailable display now produces an explicit connection error instead of advertising a nonexistent display and waiting for media. Session-end reasons are included in client diagnostics.
- Optional audio capture ending no longer cancels a healthy video session. Capture startup failures can reach the client before the connection closes.

The fix was verified on a Mac mini from a sleeping-display state: connecting restored the real display and rendered a non-black remote picture without manual wake. Related host, client and daemon tests passed (213 passed, 2 ignored), including display admission, resume, missing-display and audio-end regressions. This acceptance did not measure audio output or WAN performance.

The desktop app requires Apple Silicon and macOS 26 or later. RVP remains protocol v1. Relay packages retain Linux x86_64 / ARM64 and macOS Universal support.

This GitHub prerelease does not upload or submit an iOS App Store build. The stable update channel remains on `0.1.5`; select Beta in Software Update to receive this release. Update the host to receive the sleeping-display fix.
