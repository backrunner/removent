# Implementation Review (2026-09-06)

## Findings fixed

- Live decoded frames used lossless/unbounded paths between the decoder and GPUI. A latest-value slot now bounds memory and removes stale frames before they reach the renderer.
- Viewer frame upload swapped BGRA channels on every frame even though GPUI `RenderImage` expects BGRA. The copy was removed; retired sprite-atlas images are explicitly dropped.
- VideoToolbox decode now requests BGRA output, avoiding a scalar YUV conversion when the system can provide the target format.
- Encoder IOSurface input is allocated once per session and reused with stride-aware row copies.
- Closing an old viewer could disconnect a newer session; session generations now guard disconnect and input forwarding.
- App and daemon could race while creating identity files on a fresh data directory. Initialization is serialized and key creation uses `create_new` with restrictive permissions.
- Search filters by name or address. Manual IP and PIN dialogs support Enter and reject malformed PINs. Viewer local shortcuts are Ctrl+Cmd+Esc and Ctrl+Cmd+F; bare Escape/Cmd+F are forwarded to the remote Mac.
- Tray status rebuilds are suppressed when the status payload is unchanged.
- Settings now commit their in-memory value only after a successful atomic save.
  Theme, language, admission and update controls surface failures consistently;
  device name and VNC credentials have separate, nearby Save actions.

## Measurements

On a Mac16,10 (Apple Silicon, release build, 1280x720): HEVC encode P50 3.17 ms, encode-to-decode P50 4.27 ms; H.264 P50 3.13/4.38 ms. Software AV1 measured 19.2 ms encode P50 and 112.9 ms encode-to-decode P50 (P95 444 ms), so HEVC remains the default. Static-frame dedup skipped 99.2% of unchanged frames.

Development launches logged 178–1767 ms from entry to the first GPUI frame
callback; several later samples ran alongside Rust/Swift compilation. These are
observations under varying machine load, not a controlled cold-start comparison. The initial stable idle sample was 95.7 MiB RSS / 0.5% CPU;
later background samples fell to 13–37 MiB as resident memory changed. RSS excludes
some GPU/system allocations and should not be treated as total physical footprint.
No before/after percentage improvement or active-session memory ceiling is claimed.

The live pipeline now has one unread decoded frame per channel (client → engine,
engine → viewer): about 15.8 MiB combined at 1920×1080, excluding current rendering,
in-flight callbacks, codec surfaces and network buffers. Previously the decoder and
viewer intermediaries could accumulate without a bound. Idle decode delivery now
uses callback notifications rather than a 2 ms polling timer (500 scheduled wakeups/s).

Reproduce the codec workload with:

```sh
cargo run --release -p removent-media-codec --example benchmark
```

This moving-marker test is largely static and is not representative of full-screen
video, rapid scrolling or two-machine capture-to-display latency. Opus 48 kHz stereo
10 ms frames measured 0.041 ms encode P50 and 0.009 ms decode P50.

## UI and development workflow

The home page uses a quiet macOS utility layout: a device sidebar, direct IP
connection form and local sharing section. Promotional copy, oversized call-to-action
buttons, nested cards and duplicate host switches were removed. Plain groups and
hairline dividers carry the hierarchy; input borders and action buttons align at
32px. Dark and light palettes, focus states, selector tracks, typography, radii and
modal motion now follow a consistent scale.

Selectors use focusable buttons. Cmd+L opens and focuses the connection form,
Cmd+F focuses device search, Cmd+, opens settings, and Escape closes settings.
Device name and VNC credentials save beside their fields; Enter submits them.
Language changes also update input placeholders immediately. A forced settings-write
failure was exercised: the error appeared and both disk and selected theme remained
unchanged. Successful device-name save and theme/language changes were exercised
through Tab/Enter navigation. Invalid IP submission was checked in the running app.

Dark Chinese and light English 960×640 windows were launched and captured; home
and settings were also inspected at the 720×480 minimum size. Missing-device
discovery no longer animates indefinitely. Permission preflight results are cached
and refreshed on activation, not queried on each render.

The FPS badge no longer labels a static desktop as an unhealthy connection: exact
frame deduplication makes low frame cadence normal. Accurate RTT/loss health still
needs telemetry (below).

`scripts/dev.sh` builds app, daemon and Swift tray incrementally, selects an installed
Xcode without changing system settings, uses isolated `userdata/dev`, and supervises
only its own child PIDs. `--no-build`, `--no-tray`, `--build-only` and `--help` are
available. Scheduled release checks are skipped during this development session.
Existing daemon reuse is refused, so another session is not silently taken over.
The script's startup, duplicate-session refusal and cleanup were exercised.

## Open review findings

These existing issues remain follow-up work; this review does not certify the whole
application as bug-free.

1. **Input delivery under congestion — fixed in the [September 7 review](review-2026-09-07.md).**
   Motion now leaves reserved FIFO capacity for transitions; an undeliverable
   transition closes the affected session with an explicit error instead of
   silently dropping the event. Motion coalescing remains an optional optimization.
2. **P1 — adaptation is not fully connected in production.**
   `ClientSession::send_stats` exists, but the app does not call it periodically.
   `spawn_video_loop` increments `SendGate` immediately before an awaited write
   and decrements after it, so this serial path does not build the queue depth
   needed by its downgrade thresholds. Add measured receive/decode/transport
   telemetry and drive adaptation from actual write pressure. Avoid arbitrary
   dropping of encoded reference frames.
3. **P2 — blocking codec work shares Tokio workers.** `spawn_video_loop` encodes
   synchronously, and `video_recv_loop` submits decoding synchronously. Software
   AV1 can monopolize a worker. Dedicated bounded codec workers and an eventual
   IOSurface-to-GPU rendering path are larger optimizations worth measuring.

## Remaining validation

ScreenCaptureKit and VideoToolbox behavior require a real macOS permission grant and two machines for end-to-end latency, dropped-frame recovery, audio behavior, and TCC transitions. Workspace tests (including real hardware codec roundtrips, latest-frame channel,
concurrent identity initialization and shortcut regressions), tray integration,
`cargo fmt --all --check`, and Clippy with `-D warnings` pass. The tray fixture was
updated to include the permission fields required by its current IPC status model.
The toolchain reports pre-existing future-compatibility notices in `block` and
`proc-macro-error2`.

Two-machine long-duration video/audio, constrained Wi-Fi, physical GPU footprint,
macOS 13 compatibility, missing-permission flows, and real IPv6 LAN connections have
not been measured here. The app now chooses an IPv6 QUIC bind address for an IPv6
peer, but that change still needs a real-network smoke test.
