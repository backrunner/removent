# 0.1.8 正式修复版验收

日期：2026-10-22。产品修复和本地审查见 [0.1.7 候选审查](release-0.1.7-review-2026-10-22.md)。`v0.1.7` 的不可变 tag 保留，该候选未公开发布，正式修复使用 `0.1.8`。

## 远端失败复核与修复

首次 [CI 39657544887](https://github.com/backrunner/removent/actions/runs/39657544887) 的 Removent workspace、官网与浏览器检查通过，但新增的完整 mDNS 测试在 macOS runner 的物理网卡上出现 `No route to host`。75 项库测试通过，8 项网络夹具失败。使用私有端口与 loopback 的主机名失效、接口恢复和刷新测试通过。发布门禁拦截了该候选，没有上传公开资产。

- 网络单元夹具显式选择 IPv4 loopback；集成和 shutdown 夹具选择同一 loopback 接口的实际 IPv4/IPv6 地址，保留 IPv6 link-local 地址。所有断言继续通过真实 UDP 组播/单播执行，缺少必要接口时报错，不能静默跳过。
- legacy unicast 查询既绑定 loopback 源地址，也设置 `IP_MULTICAST_IF`，避免 macOS 使用其他网卡路由组播请求。查询仍从临时端口发出，接收 socket 不加入组播组，继续验证单播响应、查询 ID 与记录格式。
- 接口禁用测试先要求服务发现和缓存填充成功，再检查禁用后的缓存失效，最后要求重新启用后恢复发现，排除空缓存导致的误报。
- 生产 daemon 的接口选择没有改变。多接口缓存隔离与查询回归仍使用独立接口 ID 检查实际报文。
- 完整 mDNS 测试和内存探针放入独立必需的 CI job，与 workspace 检查并行运行；开发打包必须等待两者通过。未缩小检查范围。
- workspace 版本、锁文件中的 14 个 Removent 包、官网发布入口与浏览器断言改为 `0.1.8`。

## 验证状态

本地复核结果：

- 完整 mDNS 测试通过：83 项库单元、3 项地址解析、39 项集成、8 项 shutdown、4 项文档测试，共 137 项通过，3 项原有文档忽略。自定义端口隔离又单独复核通过。
- UDP 内存探针 5 轮共 20,000 条记录通过：publisher 响应缓存始终为 0，browser 每轮过期后 SRV/TXT 为 0、后台定时器回到 1，最终物理内存 4240 KiB。
- workspace/vendor 格式、布局、diff 空白和脚本检查通过；Python 检查保留 1 项原有跳过。
- 官网类型检查 0 错误/警告，静态构建通过。Chromium/WebKit 全部 40 项通过。一次 WebKit 在建立 page 夹具时超时，随后完整重跑 40 项通过，未修改页面或放宽断言。
- 产品源码与此前通过 579 项 workspace 测试、Clippy 和跨平台 Relay 的候选一致，本轮追加修改集中在测试夹具、CI 编排、版本与发布入口。

提交推送后，远端完整验收仍须通过才创建 `v0.1.8` tag。正式发布只使用同一提交通过的 CI、Relay 和 Release 工作流，并核验公开的安装包、校验和、更新签名与公证。

## 第二次远端验证

[CI 39662421610](https://github.com/backrunner/removent/actions/runs/39662421610) 的官网与 Clippy 通过；mDNS 库 83 项和地址解析 3 项全部通过。集成测试 35 项通过、4 项 IPv6 相关失败，IPv4 与缓存禁用/恢复断言均通过。runner 的 `lo0` 有 `::1` 和 `fe80::1`，但测试只收到 IPv4 数据。

追加的 CI 网络预检显式建立 `ff02::fb%lo0` 的 host 路由，独立使用真实 UDP 验证 IPv4 和 IPv6 组播回环；网络不可用时直接失败。完整协议套件仍全部必跑，并启用失败用例的详细协议日志。预检在本机两种协议均通过。该轮没有创建发布 tag，失败的 CI 已取消，以便重新验收修正后的提交。同提交的 Relay 五项任务全部通过。
