# 非全屏 CLI 组件

CLI 遵循 [UI 设计规范](ui-design.md) 的 Quiet Control 风格。交互在当前终端内完成，不进入备用屏幕，不清空终端或 shell 历史。默认界面仅使用终端调色板的语义色、细线边框和固定宽度的选中行。

## 组件与职责

- `components::Card`：标题、说明、对齐键值、分隔线与完整值的换行。状态使用独立标签，颜色之外始终有文字含义。
- `components::choose`：搜索、循环选择、分页、当前值与分类说明。搜索后的索引映射回原始操作，避免筛选后执行错误的设置。
- `components::input_validated`：编辑光标、粘贴、取消和就地校验；不丢弃无效草稿。秘密输入只展示固定标记，不泄露字符或长度。
- `components::confirm`：默认否，支持左右键、Y/N 与 Enter，说明完整展示后才允许确认。
- `components::progress`：超过 180 毫秒才出现单行活动指示；完成、出错或取消时清除其自身行。
- `components::results`：服务状态、权限、会话、身份与配对卡片。设置、错误和 ping 结果复用同一布局原语。

## 输入和输出边界

一个交互会话持有原始输入模式，避免组件切换期间快速输入被回显或丢弃。每个活动组件只管理自身占用的有限行数；结果单独追加到历史。组件退出后恢复光标，整个会话退出或 Ctrl+C 时恢复原终端状态。

宽度计算、换行和省略统一使用字符显示宽度，并处理中文标点禁则。选择态不改变行宽。终端缩小时不根据失效坐标擦除旧快照，优先保留历史；空间不足时暂停操作并提示调整窗口。

JSON 模式和管道不产生组件控制序列。服务、配对与身份保持原有 JSON 结构；设置单值查询和其他已有脚本契约继续保留。诊断仅在 `--verbose` 时输出到终端。

## 验收

`cargo test -p removent-cli --locked` 包含布局、过滤索引和真实 PTY 子进程测试。PTY 测试覆盖搜索、快速输入、密码隐藏、取消恢复、确认不保存、粘贴防提交、无效值校验、窗口缩放、进度清理与 JSON 隔离。视觉验收应检查真实 CLI 输出在深浅终端调色板下的呈现，并将终端模拟器回放与原生终端截图明确区分。
